| `MERISTEM-SCM-R001` | **Development loop on changesets.** The coding harness edits in a virtual workspace. It runs fast gates in its sandbox. It submits through the repository-manager connector tools (`source.commit`/`source.land`). It reacts to `SOURCE_CONFLICT{paths}` (MEDULLA-SCM-R003) by rebasing on the new head and retrying. Local git is not required. File it touches: `meristem/harness/changeset_loop.py`. Planned test: `tests/harness/test_changeset_loop.py::test_changeset_loop_rebases_on_conflict`. | One edit cycle lands one changeset through `source.commit`. A `SOURCE_CONFLICT{paths}` refusal triggers one rebase and one retry. The loop holds no store and no local git state. |
| `MERISTEM-SCM-R002` | **Symbol-level edits in the run loop.** The coding harness must submit a code change as a symbol edit through `source.edit_symbol` (ARBORA-OPS-R848.4, MEDULLA-SCM-R013) when the file has a parser. On `EDIT_ROUNDTRIP_MISMATCH` it returns the refusal to the model as a step observation. File it touches: `meristem/harness/changeset_loop.py`. | `tests/harness/test_changeset_loop.py::test_symbol_edit_retries_once_on_stale_base` lands one edit after one stale refusal.
