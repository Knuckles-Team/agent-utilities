# MERISTEM-HARNESS-CYCLE — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A child row `.n` is one five-minute unit of work. A row names the file it touches and the test that proves it. The generator sets each row's state in `status.json`.

| `MERISTEM-HARNESS-CYCLE-R001` | **Harness evolution cycle (rollup).** For one task, the harness proposes k candidate component versions. It probes each under identical conditions. It composes the adopted harness through the decision of MEDULLA-DECISION-ENGINE-R803. It persists the version, the contrast and the lesson as graph facts. It reflects the lesson for the next task. The candidate budget k is the candidate slot count of the stage allocation from MEDULLA-DECISION-ENGINE-R136.3. Below two slots the cycle abstains with `budget_below_contrast`. An abstention keeps the current harness. Children `.1` to `.13` deliver it. | See each child. |
| `MERISTEM-HARNESS-CYCLE-R001.1` | **Model.** Add `HarnessCandidate{candidate_id, task_ref, component_kind, component_version_ref, seed, model_ref, budget_ref}` and `CycleOutcome{task_ref, k, adopted_version_ref, abstain_reason, contrast_ref, lesson_ref}` in `meristem/harness/harness_cycle.py`. Both are frozen dataclasses. `abstain_reason` is the closed set `budget_below_contrast`, `no_candidates`, `probe_trace_missing`, `compose_abstention` or `measurement_unavailable`. Planned test: `tests/harness/test_harness_cycle.py::model_round_trips`. | A dataclass round trip keeps every field and rejects an open refusal code. |
