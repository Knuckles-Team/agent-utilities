| `MERISTEM-HARNESS-CYCLE-R001` | **Harness evolution cycle (rollup).** Stage: post-run evolution tick, one per completed task. Caller: arbora host (ARBORA-HOST-R035) → `meristem/harness/harness_cycle.py::drive_cycle_tick` → `run_cycle_tick`. For one task, the harness proposes k candidate component versions and probes each under identical conditions. The engine measures the contrast from the stored probe traces and decides the adoption (MEDULLA-DECISION-ENGINE-R803, MEDULLA-DECISION-ENGINE-R803.7). The harness stores the adoption, the contrast and the lesson through one `DecisionLog` call (MEDULLA-DECISION-ENGINE-R803.8) and reflects the lesson. The harness is the `record_outcome` producer of the run history that MEDULLA-DECISION-ENGINE-R160 validates (MEDULLA-TYPED-PACKS-R100.7). Each component version is a revision of `Definition { HarnessComponent, component_id }`. Each adoption is an evaluated revision of `Definition { HarnessBundle, <agent_ref>:<task_class> }` (MEDULLA-DECISION-ENGINE-R805.10). Champion moves belong to MEDULLA-DECISION-ENGINE-R805. The candidate count k is the slot count of the stage allocation of MEDULLA-DECISION-ENGINE-R136.3. The bounds are `knob harness_evolution.min_candidates` and `knob harness_evolution.max_candidates` (MEDULLA-DECISION-ENGINE-R179.7). The harness holds no threshold; its local minimum is a fallback default only (child `.15`). Below the minimum the cycle abstains with `budget_below_contrast`, and an abstention keeps the current harness. Children `.1` to `.15` deliver it.
