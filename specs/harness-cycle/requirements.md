# AU-HARNESS-CYCLE — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A child row `.n` is one five-minute unit of work. A row names the file it touches and the test that proves it. The generator sets each row's state in `status.json`.

| ID | Requirement | Acceptance |
|---|---|---|
| `AU-HARNESS-CYCLE-R001` | **Harness evolution cycle (rollup).** For one task, the harness proposes k candidate component versions. It probes each under identical conditions. It composes the adopted harness through the decision of EG-DECISION-ENGINE-R803. It persists the version, the contrast and the lesson as graph facts. It reflects the lesson for the next task. The candidate budget k is the candidate slot count of the stage allocation from EG-DECISION-ENGINE-R136.3. Below two slots the cycle abstains with `budget_below_contrast`. An abstention keeps the current harness. Children `.1` to `.9` deliver it. [arXiv:2610.14224] | See each child. |
| `AU-HARNESS-CYCLE-R001.1` | **Model.** Add `HarnessCandidate{candidate_id, task_ref, component_kind, component_version_ref, seed, model_ref, budget_ref}` and `CycleOutcome{task_ref, k, adopted_version_ref, abstain_reason, contrast_ref, lesson_ref}` in `agent_utilities/harness/harness_cycle.py`. Both are frozen dataclasses. `abstain_reason` is the closed set `budget_below_contrast`, `no_candidates`, `probe_trace_missing` or `compose_abstention`. Planned test: `tests/harness/test_harness_cycle.py::model_round_trips`. | A dataclass round trip keeps every field and rejects an open refusal code. |
| `AU-HARNESS-CYCLE-R001.2` | **Propose.** The propose step builds one candidate per returned version. It queries the improvement library of EG-ORCH-VOCAB-R802.3 for the task class. The cycle stores nothing. An empty answer yields the refusal `no_candidates` and keeps the current harness. Planned test: `tests/harness/test_harness_cycle.py::propose_queries_lesson_library`. | One candidate per returned version, and no write. |
| `AU-HARNESS-CYCLE-R001.3` | **Probe.** The probe step enters each candidate through `execute_graph` at `agent_utilities/graph/runner.py:80`. It shares one task, seed, model and budget. The conditions digest binds the shared values. The probe writes no graph state. A lost trace yields the refusal `probe_trace_missing`. Planned test: `tests/harness/test_harness_cycle.py::probe_shares_conditions_and_records_trace`. | Each probe carries the same conditions digest and one trace. |
| `AU-HARNESS-CYCLE-R001.4` | **Compose.** The compose step sends the probe traces and the contrasts. It calls the served `Decide` under the `HARNESS_CONTRAST` question kind of EG-DECISION-ENGINE-R803. The cycle applies no local ranking. The engine answer is the adoption or the abstention. Planned test: `tests/harness/test_harness_cycle.py::compose_delegates_to_engine`. | One `Decide` call per tick, and no ranking code in the cycle. |
| `AU-HARNESS-CYCLE-R001.5` | **Persist.** The persist step writes the adopted version, the contrast and the lesson through the generated-client envelopes of EG-ORCH-VOCAB-R801.2 and EG-ORCH-VOCAB-R802. The in-run harness switch reuses `apply_edits` at `agent_utilities/harness/edit_engine.py:457`. The step writes no other state. Planned test: `tests/harness/test_harness_cycle.py::persist_envelopes_switch_harness`. | Three envelopes and one `apply_edits` call per adoption. |
| `AU-HARNESS-CYCLE-R001.6` | **Reflect.** The reflect step submits the lesson only when the compose step adopted a candidate. It cites the evidence runs by trace id. Retention belongs to the behavior of EG-ORCH-VOCAB-R802.2. Planned test: `tests/harness/test_harness_cycle.py::reflect_submits_lesson_on_adoption`. | One lesson on adoption, and none on abstention. |
| `AU-HARNESS-CYCLE-R001.7` | **Refusal.** The cycle refuses with a typed code and keeps the current harness. `budget_below_contrast` fires on an allocation under two candidate slots. `no_candidates` fires on an empty library answer. `probe_trace_missing` fires on a lost probe trace. `compose_abstention` fires on the engine abstention and persists no adoption. Planned test: `tests/harness/test_harness_cycle.py::refusals_keep_harness`. | Each case returns its code and persists nothing. |
| `AU-HARNESS-CYCLE-R001.8` | **Wiring.** `agent_utilities/host_ports.py` gains a `HarnessCycleProvider` port beside `RunDecisionProvider`. arbora registers the driver at startup. The provider drives one cycle tick per task and reports through the existing `RunEventSink`. Without a registered provider the port fails closed. Planned test: `tests/harness/test_harness_cycle.py::port_fails_closed_without_provider`. | The unregistered port raises the closed failure. |
| `AU-HARNESS-CYCLE-R001.9` | **Hot-path proof.** The entry point is the served cycle with two candidates and k = 2. The test reads the graph afterwards and observes the adopted version, the contrast and the lesson. The next propose query returns the stored lesson. Planned test: `tests/harness/test_harness_cycle_served.py::test_cycle_double_shows_lesson_to_next_propose`. | The graph double shows all three facts, and the next tick proposes from the lesson. |
