# AU-RETRIEVAL requirements

| ID | Requirement | Verification |
|---|---|---|
| `AU-RETRIEVAL-R001` | **Benchmark structure-aware retrieval against served hybrid search.** AU benchmarks constrained section-leaf selection against hierarchical-document retrieval and the production hybrid vector-plus-graph retrieval path, using a versioned synthetic fixture corpus and optionally held-out ecosystem documents, under identical visible candidate sets and token budgets, measuring citation validity, visibility correctness, p50/p95 latency and index/update cost. | A reproducible benchmark report compares all methods on the fixture corpus with Recall@1/3, nDCG, citation-validity and latency metrics, and adoption requires a statistically defensible gain on a held-out set with no visibility or citation regression. |
| `AU-RETRIEVAL-R002` | **Studied retrieval techniques enter only through the benchmark.** AU must run a technique proposed by the study pipeline through the `AU-RETRIEVAL-R001` harness under identical candidate sets and budgets. AU must refuse admission without a paired result. | `tests/retrieval/test_study_admission.py` proves refusal without a result and acceptance with one. |
| `AU-RETRIEVAL-R003` | **Iterative memory expansion stops at a declared budget and abstains.** Agent memory access expands from cues through associative tags to content. It prunes paths using the evidence gathered so far and stops at a declared expansion budget. An exhausted budget returns abstention with the partial path. | See children `AU-RETRIEVAL-R003.1` to `AU-RETRIEVAL-R003.6`. |
| `AU-RETRIEVAL-R003.1` | **Model.** `ExpansionBudget` holds a maximum step count, a maximum node count and a token cap. `ExpansionPath` holds the ordered cue, tag and content nodes with the evidence score of each step. Both live in `agent_utilities/knowledge_graph/retrieval/`. | `tests/retrieval/test_memory_expansion.py::test_budget_and_path_types`. |
| `AU-RETRIEVAL-R003.2` | **Behavior.** Each step must expand the best-scoring frontier node, then prune paths whose evidence score falls below a named, replaceable threshold. Expansion must stop on enough evidence or on any budget limit [arXiv:2606.06036]. | `tests/retrieval/test_memory_expansion.py::test_prune_and_stop_rules`. |
| `AU-RETRIEVAL-R003.3` | **Wiring.** The expansion attaches to `retrieve_hybrid_budgeted` (`agent_utilities/knowledge_graph/retrieval/hybrid_retriever.py:1898`), which calls `retrieve_hybrid` today. This row creates the call site that passes cue nodes into the expansion when the caller requests memory mode. | `tests/retrieval/test_memory_expansion.py::test_memory_mode_reaches_expansion`. |
| `AU-RETRIEVAL-R003.4` | **Refusal.** An exhausted budget must return `RetrievalAbstention` with reason `expansion_budget_exhausted` and the partial `ExpansionPath`. The retriever must not return the partial path as an answer. | `tests/retrieval/test_memory_expansion.py::test_exhausted_budget_abstains`. |
| `AU-RETRIEVAL-R003.5` | **Evidence.** The retrieval trace must record the steps taken, the nodes pruned, the budget spent and the stop reason. The paired benchmark in `AU-RETRIEVAL-R001` must report these fields. | `tests/retrieval/test_memory_expansion.py::test_trace_budget_fields`. |
| `AU-RETRIEVAL-R003.6` | **Hot-path proof.** The entry point is the served memory retrieval operation. A cue with enough evidence must answer within budget. A cue in a sparse graph must abstain with the partial path. The test observes the trace for both. | `tests/retrieval/test_memory_expansion_served.py::test_served_memory_retrieval_budget`. |
| `AU-RETRIEVAL-R004` | **Insufficient evidence requests more retrieval, then abstains under strict fallback.** The generator must detect insufficient retrieved evidence and request another retrieval round. Under strict fallback, it must abstain and never fabricate an answer. | See children `AU-RETRIEVAL-R004.1` to `AU-RETRIEVAL-R004.6`. |
| `AU-RETRIEVAL-R004.1` | **Model.** `EvidenceSufficiency` holds a verdict (`sufficient`, `insufficient`), the evidence count and the reason. `FallbackPolicy` is the closed set `lenient` and `strict`. Both live beside `ExecutableRagProgram` in `agent_utilities/knowledge_graph/retrieval/executable_rag.py`, which has the marker test `_is_insufficient` (line 87) but no typed verdict. | `tests/retrieval/test_insufficient_evidence.py::test_sufficiency_and_policy_types`. |
| `AU-RETRIEVAL-R004.2` | **Behavior.** The existing repair in `_retrieve_with_repair` (`executable_rag.py:198`) boosts k and switches mode. After `max_repairs` rounds with a verdict still `insufficient`, the policy decides. `lenient` returns the extractive answer. `strict` abstains. The sufficiency rule is a named, replaceable default. | `tests/retrieval/test_insufficient_evidence.py::test_repair_then_policy`. |
| `AU-RETRIEVAL-R004.3` | **Wiring.** `ExecutableRagProgram.run` (`executable_rag.py:236`) calls `answer_fn` at line 256 and at line 266, and reads only `_is_insufficient`. The row attaches the typed verdict and policy there. `HybridRetriever.retrieve_executable` (`hybrid_retriever.py:1917`) passes the policy. Its production caller is `_analysis_action_executable_rag` (`agent_utilities/mcp/tools/analysis_tools.py:2294`). The default answerer at `hybrid_retriever.py:1957` returns the string `insufficient evidence` as an answer today. | `tests/retrieval/test_insufficient_evidence.py::test_policy_reaches_answer_step`. |
| `AU-RETRIEVAL-R004.4` | **Refusal.** Under `strict`, the program must return `RetrievalAbstention` with reason `insufficient_evidence` and the evidence gathered. It must not return an answer string. The `RetrievalAbstention` type is the one defined in `AU-RETRIEVAL-R003.4`. | `tests/retrieval/test_insufficient_evidence.py::test_strict_abstains_without_answer`. |
| `AU-RETRIEVAL-R004.5` | **Evidence.** The `StepTrace` list (`executable_rag.py:66`) must record each repair round, the verdict, the policy and the final outcome (`answered` or `abstained`). The benchmark in `AU-RETRIEVAL-R001` must report the abstention rate. | `tests/retrieval/test_insufficient_evidence.py::test_trace_records_rounds_and_outcome`. |
| `AU-RETRIEVAL-R004.6` | **Hot-path proof.** The entry point is the served `executable_rag` analysis action. A question with enough evidence must answer. A question over an empty graph under `strict` must abstain after the repair rounds. The test observes the trace for both. | `tests/retrieval/test_insufficient_evidence_served.py::test_served_executable_rag_abstains_under_strict`. |
| `AU-RETRIEVAL-R005` | **Iterative retrieval stops on answer repeat plus a calibrated confidence margin.** The stop rule must fire when the model repeats its previous-round answer. The per-round confidence margin must also exceed a fixed threshold [arXiv:2606.13814]. The rule uses no learned component. The stop reason is traced. | See children `AU-RETRIEVAL-R005.1` to `AU-RETRIEVAL-R005.6`. |
| `AU-RETRIEVAL-R005.1` | **Model.** `RoundConfidence` holds the round index, the answer confidence and the calibrated baseline for that round. `StopDecision` (`agent_utilities/knowledge_graph/retrieval/adaptive_stopping.py:39`) gains the field `margin`. `IterativeStopper.update` (line 151) takes no confidence today. | `tests/retrieval/test_confidence_margin_stop.py::test_round_confidence_and_decision_types`. |
| `AU-RETRIEVAL-R005.2` | **Behavior.** `IterativeStopper` already stops on `answer_repeat` (`adaptive_stopping.py:80`). The new rule must stop only when the answer repeats and `confidence - baseline` exceeds `margin_threshold`. The default threshold is a named, replaceable constant. The calibration table maps each round to a baseline. A fixed table must hold no learned parameter. | `tests/retrieval/test_confidence_margin_stop.py::test_repeat_needs_margin`. |
| `AU-RETRIEVAL-R005.3` | **Wiring.** The stopper is built and updated at `iterative_expansion.py:171` and `iterative_expansion.py:229`, and at `active_reconstruction.py:237` and `active_reconstruction.py:282`. Neither call passes a confidence. The row passes the round confidence at both calls. The production caller of the first is `engine_query.py:1509` through `IterativeQueryExpander.run`. | `tests/retrieval/test_confidence_margin_stop.py::test_expander_passes_confidence`. |
| `AU-RETRIEVAL-R005.4` | **Refusal.** A call without a confidence must keep the repeat-only behavior and must record `margin` as `unavailable`. A confidence outside 0 to 1 must raise a typed validation error. The stopper must not guess a confidence. | `tests/retrieval/test_confidence_margin_stop.py::test_missing_or_invalid_confidence`. |
| `AU-RETRIEVAL-R005.5` | **Evidence.** The retrieval trace must record the stop reason, the margin, the threshold and the round count at the stop. The reason set gains `answer_repeat_confident`. The benchmark in `AU-RETRIEVAL-R001` must report rounds saved. | `tests/retrieval/test_confidence_margin_stop.py::test_trace_stop_reason_fields`. |
| `AU-RETRIEVAL-R005.6` | **Hot-path proof.** The entry point is the query operation in `engine_query.py` that builds the expander. A scripted loop that repeats a confident answer must stop early with the new reason. A repeat with a low margin must continue. The test observes the stop reason in the trace. | `tests/retrieval/test_confidence_margin_stop_served.py::test_served_query_stops_on_confident_repeat`. |
| `AU-RETRIEVAL-R006` | **Answer step arbitrates between model prior and retrieved evidence.** When the model prior and the retrieved evidence disagree, the answer step must arbitrate with a training-free confidence margin [arXiv:2606.08397]. Below the margin it must abstain and record both candidates with their evidence classes. | See children `AU-RETRIEVAL-R006.1` to `AU-RETRIEVAL-R006.6`. |
| `AU-RETRIEVAL-R006.1` | **Model.** `ArbitrationInput` holds the prior candidate, the evidence candidate, a confidence for each and an `evidence_class` for each. `ArbitrationResult` holds the chosen candidate or an abstention. `EvidenceClass` (`agent_utilities/api/agent_control_contracts.py:73`) has the one value `claim` today. The row adds the classes `parametric` and `retrieved`. No arbitration type exists; the searches `arbitrat`, `parametric`, `closed-book` and `margin` found none on a retrieval path. | `tests/retrieval/test_prior_evidence_arbitration.py::test_arbitration_types`. |
| `AU-RETRIEVAL-R006.2` | **Behavior.** The arbiter must compare the two confidences. It must choose the candidate whose confidence leads by at least `arbitration_margin`. Candidates that agree need no arbitration. The margin is a named, replaceable default and uses no trained component. The prior comes from a probe that answers without retrieval, in the manner of the closed-book probe at `agent_utilities/knowledge_graph/search_synthesis/shortcut_risks.py:42`. | `tests/retrieval/test_prior_evidence_arbitration.py::test_margin_choice_and_agreement`. |
| `AU-RETRIEVAL-R006.3` | **Wiring.** The arbiter attaches at the answer step of `ExecutableRagProgram.run` (`executable_rag.py:256`), after `answer_fn` and before the answer is stored. `HybridRetriever.retrieve_executable` (`hybrid_retriever.py:1917`) supplies the prior probe. Its production caller is `_analysis_action_executable_rag` (`analysis_tools.py:2294`). No production caller reaches an arbiter today, because none exists. | `tests/retrieval/test_prior_evidence_arbitration.py::test_arbiter_runs_at_answer_step`. |
| `AU-RETRIEVAL-R006.4` | **Refusal.** Below the margin the step must return `RetrievalAbstention` with reason `prior_evidence_conflict`. It must carry both candidates and both evidence classes. The step must not pick the higher score alone. | `tests/retrieval/test_prior_evidence_arbitration.py::test_below_margin_abstains_with_both`. |
| `AU-RETRIEVAL-R006.5` | **Evidence.** The trace must record both candidates, both confidences, the margin used, the evidence classes and the decision. The benchmark in `AU-RETRIEVAL-R001` must report the conflict rate and the abstention rate. | `tests/retrieval/test_prior_evidence_arbitration.py::test_trace_records_both_candidates`. |
| `AU-RETRIEVAL-R006.6` | **Hot-path proof.** The entry point is the served `executable_rag` analysis action. A conflict with a clear margin must return the leading candidate. A conflict inside the margin must abstain with both candidates. The test observes the trace for both. | `tests/retrieval/test_prior_evidence_arbitration_served.py::test_served_conflict_arbitration`. |
