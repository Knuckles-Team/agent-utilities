# Agent-utilities gate reference

Deep reference for `agent-utilities-development`: every architecture /
anti-sprawl hook declared in `.config/pre-commit.yaml`, its stage, and exactly
what it refuses — including which clauses are absolute, which are diff-scoped,
which are advisory or inert today, and the one surviving live ratchet. The parent
[`SKILL.md`](../SKILL.md) keeps the guardrails, the differential-merge rule and
the workflow. Per G2, read the row here (and the gate script's own docstring)
before citing what a gate enforces — a `.config/pre-commit.yaml` comment is not
the gate's behaviour.

## The architecture and anti-sprawl gates

| Hook id | Stage | Refuses |
|---|---|---|
| `check-import-cycles` | pre-commit, `agent_utilities/**.py` | Any **eager** (module-load) import cycle. **Absolute zero, no baseline, no ratchet.** Function-local and `TYPE_CHECKING` imports are excluded *by design* — "simplifying" that away refires against the raw-SCC debt and forces a ratchet the workspace forbids |
| `guardrail-sprawl` | always_run | `*_v2.py` / `*_old.py` / `*_new.py`, `.orig` / `.rej` / `.bak`, the literal `# --- Merged from` marker, tracked binaries > 1,000,000 bytes |
| `check-no-env-sprawl` | always_run | ★ A bare env **read of ANY variable**, not just `KG_*`/`GRAPH_*`/`EPISTEMIC_*` — `os.environ.get("VAULT_ADDR")` and `OTEL_*`, `AGENT_*`, connector creds are all inside the gate (`scripts/check_no_env_sprawl.py:47-49`). Both read forms are caught: the read APIs `os.environ.get(...)`/`os.getenv(...)` **and subscript reads `os.environ["X"]`** (a trailing `=` → a write, exempt). Every read must be a typed `AgentConfig` field or `config.setting(...)`. Allowlisted files are exactly three: `core/config.py`, `core/_env.py`, `core/paths.py`. **`MAX = 0`, a module constant — absolute, no baseline file, no `--update-baseline`** |
| `guardrail-entrypoint-engine-authority` | always_run | An entrypoint calling `IntelligenceGraphEngine(...)` directly or `create_backend(backend_type=…)`. Use `.get_active()` / `.get_or_create()` — the singleton race made whichever entrypoint got there first the engine authority for the whole process (D-WD-7) |
| `guardrail-surface-parity` | `files: ^agent_utilities/.*` | **Two clauses of different strength.** (1) Tool↔route drift — a tool with no REST twin in `ACTION_TOOL_ROUTES` or a route with no tool: **hard, absolute, unconditional, no baseline, ever**; the repo is at zero and stays there. (2) Feature reachability — a capability module reachable from *neither* surface root: ★ **DIFF-SCOPED, not absolute.** Only a capability module **newly added by this change** (absent from `HEAD`) and unexposed fails; the ~**45** pre-existing unexposed modules are printed as an unconditional census on every run and are *backlog, not gated* (the 45-entry `surface_parity_baseline.txt` ratchet was retired at exact parity with the live set — `--update-baseline` now exits 2). ★ **Documented blind spot:** a module whose *last* surface-import edge this diff **removes** becomes unexposed without being "added", so it is not caught at commit time — only as a visibly larger census on the next run. Deliberately traded off; a reviewer sees the import line disappear in the diff |
| `guardrail-openapi-coverage` | scoped | A mounted route absent from the generated OpenAPI spec, and a documented operation with no `summary`/`description`. ★ **The baseline is RETIRED** — `--update-baseline` exits 2; the gate prints the real census every run (the `.config/pre-commit.yaml` comment still describing a ratchet is stale) |
| `guardrail-no-stub` | always_run | A production stub — five distinct shapes, not one (`scripts/check_no_stub.py:24-28,59`): a `"[Mock]"` string return, the literal `dummy_embedding`, `Fallback equal-weight`, `equal weighting since`, and `raise NotImplementedError` on a line not marked `# ABSTRACT-OK`. The last four are silent-degradation markers, not placeholders — a fallback that quietly substitutes uniform weights for a real score is exactly what this gate exists to refuse |
| `check-wire-first` | scoped | A public `agent_utilities/` symbol referenced only from `tests/`, and a test file `testpaths`/CI never collects. ★ **The baseline is RETIRED** — `--update-wire-first-baseline` exits 2; orphans are an absolute zero and test-only symbols are diff-scoped against HEAD (the hook comment still describing a ratchet is stale) |
| `guardrail-removed-symbol-consumers` | manual-only | Deleting or renaming a public symbol a fleet repo still imports (`scripts/fleet_symbol_consumers.json`). **Fails closed** if that index is missing, unparseable, or > 30 days old |
| `clone-dupehound-changed-functions` | pre-commit | Whole-function structural clones among changed functions. Returns 2 — not a pass — when the binary/version/result cannot be trusted |
| `clone-jscpd-diff` / `clone-jscpd-census` | manual-only | New copied token blocks vs a base ref (diff = blocking; census = advisory, never fails) |
| `complexity-staged` | always_run | A NEW function over cyclomatic 10 / cognitive 15, or an existing one that regressed (cccc) |
| `check-skill-name-collision` | always_run | Two *installable* `SKILL.md` sharing a `name:`; two prompts in one package sharing a `task`. `skill_graphs/` is excluded — it is a KG reference corpus, not an installed namespace. ⚠ **This is the repository's ONE surviving live ratchet, and the workspace has a project-wide NO-RATCHETS rule.** `scripts/check_skill_name_collision.py` still carries a *working* `--update-baseline` that writes `scripts/skill_collision_baseline.txt` (:374-381), and `_load_baseline()` then excuses every name in it (:384-390). It behaves absolutely today for one reason only: **that file does not currently exist.** Every sibling baseline-bearing gate — `check_openapi_coverage`, `check_wiring`, `check_surface_parity`, `check_swallowed_errors`, `check_liveness`, `check_concept_governance`, `check_event_loop_blocking`, `check_no_per_element_ingest_loop` — now **exits 2** on its retired flag, and `check_tracked_privacy`'s mechanism was deleted outright. Do **not** run `--update-baseline`: one invocation re-installs the ratchet and silently grandfathers every collision then present |
| `lane-guard` | always_run | Three refusals, not two (`scripts/check_lane_guard.py`): a non-merge, non-bump commit authored in the **canonical checkout**; a hand-edited `docs/concept_reservations.yaml` (it is the fold of the per-lane fragments); and ★ **a commit made with `CARGO_TARGET_DIR` exported to a path that is not this lane's** (:157-175) — cargo's own env precedence overrides the per-lane config, defeating the PARTITION class, and a shared target dir *corrupts* concurrent worktree builds rather than merely serializing them |
| `check-root-hygiene` | always_run | Anything at the repo root outside an explicit **allowlist** (a denylist only ever catches the junk you already thought of). ★ The allowlist is **manifest-driven**: directories and non-dot files come from the sibling **`.repo-layout.toml`**, and only conventional dot-*files* are enumerated in the script (`ALLOWED_DOTFILES`); a dot-*directory* must be declared in the manifest's `[dirs]` table. Adding a root entry means editing the manifest, deliberately — not the script. ★ And its **`FORBIDDEN_ANYWHERE` set is repo-wide, not root-scoped**: self-installing ratchet artifacts (`.kissconfig`, `.complexity-baseline.json`, `.liveness_baseline.json`) are rejected anywhere in the tracked tree, and no allowlist rescues them. It reads `git ls-files`, never the filesystem, so gitignored build output cannot make it cry wolf |
| `check-import-safety` | `files: ^(agent_utilities/.*\|pyproject\.toml\|uv\.lock)$` | ★ It **imports every module under `agent_utilities` and fails on ANY exception raised at import time** — not only the POSIX-only-stdlib class. The headline case is an unconditional top-level `fcntl`/`termios`/`pwd`/`resource`/`grp` import, caught on Linux via `--simulate-windows` (it poisons those modules in `sys.modules`; it deliberately does **not** flip `sys.platform`/`os.name`). ★ **A gate's universe is not the package's universe: the hook entry carries 22 `--exclude` module exemptions** (`__main__`, `server`, `cli`, `patterns`, `mcp.tools`, `mcp.verbose_tools`, `mcp.multiplexer`, `mcp.middlewares`, `governance.lanes`, `governance.merge_queue`, `knowledge_graph.core.file_lock`/`engine_lock`/`host_lock`, …). Read the `entry:` block before assuming your module is covered. Blind spot: a lazy `def f(): import fcntl` is invisible to an import-time walk |
| `env-var-drift` | `files: ^(agent_utilities/.*\|deploy/.*\|docker/.*\|\.env\.example\|pyproject\.toml)$` | ★ **The predictable surprise for anyone adding a setting.** `python -m agent_utilities.mcp.check_env_var_drift --check` (CONCEPT:AU-OS.config.env-var-drift-guard). **The code is the only authority for which vars exist**; the declared sets are diffed against the code-read surface (`setting("X")` reads + derived `<TAG>TOOL` toggles from `register_<tag>_tools` + compose `${VAR}` substitutions in `image:`/`command:`/`entrypoint:`/`args:` + the inherited agent-utilities surface). Six findings: `DEAD` (declared, never read), `UNDOCUMENTED` (read, missing from `.env.example`), `MISSING_TOOL_MODE` (an `mcp_config*.json` `env` block or README example with no `MCP_TOOL_MODE`), `MALFORMED_VALUE` (`"${ VAR:-True }"` — no spaces inside the braces), `AGENT_VAR_IN_MCP` (an agent-runtime var sitting in an MCP-server config), `STALE_EXAMPLE`. So a new setting must land in `.env.example`, **every** `mcp_config*.json` `env` block, `docker/*compose*.yml`, and the README table in the same change |
| `guardrail-gate-meta-tests` | manual-only | A gate that cannot be shown to fail on a deliberately broken fixture (`tests/gates/`) |
| `guardrail-tracked-privacy` | always_run | Host-specific data or local identities in any tracked file |
| `guardrail-kg-skill-coverage` | manual-only | A live Graph-OS verb with no explicit claim in an `agents/graph-os.yaml` sidecar |
| `guardrail-coupling-advisory` | always_run | geniusbot importing `agent_utilities` outside the allowlisted adapter seam — ★ **ADVISORY**: its hook entry is `bash -c 'python3 scripts/check_coupling.py \|\| true'`, so it cannot fail your commit. It also covers **only** geniusbot→`agent_utilities`; it enforces nothing about `agent_utilities`'s own layering. Do not read it as coverage |
| `guardrail-parity` | always_run | ★ **INERT TODAY, BLOCKING THE MOMENT ITS SCRIPT APPEARS.** It resolves `${WORKSPACE_PARITY_SCRIPT:-<workspace>/agent-packages/scripts/check_parity.py}` and prints `SKIP` only while that file is absent — which it is, verified 2026-09-03. **Unlike `guardrail-coupling-advisory` it is NOT wrapped in `\|\| true`**: the `if [ -f "$script" ]` branch runs `python3 "$script"` bare, so its exit code fails the commit as soon as anyone creates `agent-packages/scripts/check_parity.py` or exports `WORKSPACE_PARITY_SCRIPT`. Its hook *name* still says "ADVISORY"; the wiring does not. Treat it as a live gate with an absent input, not as advisory |
